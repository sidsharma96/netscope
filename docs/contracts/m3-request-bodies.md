# Submit reviewed text and JSON

This extends the single-request GET contract with GET/POST method selection and editable POST bodies. All existing timeout, cancellation, response limits, TLS verification, no-redirect, no-retry, and explicit-Send rules remain in force, including cancellation during upload. Cancellation cannot undo server actions. Tests use only controlled local servers.

GET remains bodyless. Switching GET to POST starts with empty plain text; switching POST to GET clears its body and resets its format. The draft shortcuts are m for method, t for plain text/JSON, and b for body editing. They do not send. Header rows and Review retain their existing navigation. Text entry appends, Backspace removes one grapheme, Ctrl+u clears, Ctrl+n inserts a newline in the body, Tab inserts a tab in the body, Enter saves, and Esc cancels. q is text inside the body; Ctrl+c quits. This slice does not add paste handling or a movable cursor.

Bodies are limited to 16,384 UTF-8 bytes. Plain text uses text/plain; charset=utf-8. JSON uses application/json and requires one complete valid JSON value before review/send. Empty JSON is invalid; empty plain text is valid. JSON is validated without reserialization: whitespace and number spelling remain exactly as entered. The existing JSON parser's nesting and numeric limits remain enabled; out-of-range numbers such as 1e400 are rejected with a fixed explanation. Duplicate JSON member names are not resolved or rejected by this syntax check. The server's schema and duplicate-member interpretation are outside this validation.

The client manages Content-Type, Content-Length, and Content-Encoding as well as the existing reserved fields. No compression is applied. POST includes the exact UTF-8 byte length, including zero. GET adds neither body nor body metadata. Header selection cannot override the chosen body representation. Review shows method, format, full escaped body text, byte count, and managed fields. Body values are visible in editing and review; terminal controls are escaped in review. A changed draft requires a fresh review.

Changing any saved URL text clears the body as well as selected/manual headers. The selected method and format remain, so an emptied JSON draft needs valid content again. This reset is explained immediately. The original capture is never changed.

Eligible captures are existing bodyless GETs and POSTs whose body is explicitly empty or retained as supported plain text/JSON. Captured text is copied only for text/plain or application/json, optionally with charset=utf-8, within the body limit. Unknown encodings/media types, form parameters, multipart, and missing nonempty body data are rejected with an explanation; no body is silently discarded. Invalid captured JSON may be repaired in the editor but cannot pass review. Request Content-Encoding must be absent or identity when importing a POST draft.

Each result retains the sent method and request-body byte count, independently of later draft edits. Result and comparison views label those values. The recorded method may differ from the replayed method; equal response values do not imply equivalent operations.

Verification covers draft changes/reset/cancel, Unicode byte counts, malformed/oversized JSON, exact outgoing text/JSON/empty body bytes and headers, unchanged GET behaviour, duplicate Send, cancellation while writing, response limits, and original-capture/result provenance. Fixed buffers cover POST editing/review and results at both supported sizes; a live pseudo-terminal submits JSON to a loopback server. The book explains text and bytes before the corresponding Rust operations.
