# Saved request drafts

A named draft can be saved to a user-chosen local JSON file and reopened with `netscope --draft <file>` without a capture. Loading opens the editor, never review or Send. No captured identity, result, response history, cookies from a jar, or authorization to send is persisted. A reopened request has no capture comparison. Esc from its draft exits; its result can still be reopened with o within that session.

From a draft, w asks for a name and file path, then shows a scrollable preview of the exact encoded file. Enter on that preview explicitly writes or replaces the chosen file; Esc cancels without I/O. The name is 1–128 UTF-8 bytes, nonblank, with no controls. Paths are literal absolute or working-directory-relative paths; shell expansions such as ~ are not interpreted. Parent directories must already exist. Saving requires the request to pass model review. The original capture and draft remain unchanged after success or failure.

Version 1 has exactly version, name, url, method, format, body, and headers fields. Method is GET or POST; format is plain or json. Each header has name and value. Selected and manually added headers keep order and duplicates. The URL preserves its fragment for later review; transport still omits fragments. Body text preserves its exact content, including whitespace and number spelling inside JSON. JSON escaping in the outer file is decoded when loading. File encoding may be pretty-printed independently of body content.

Authorization, Proxy-Authorization, Cookie, Cookie2, Set-Cookie, X-Api-Key, Api-Key, X-Auth-Token, and X-Access-Token are omitted case-insensitively on save. Loading a hand-edited file containing any of them is rejected; credentials can be entered explicitly after opening. This version offers no opt-in to persist those fields. The preview states that other header values, URLs, and bodies can still contain secrets. It is a plain-text file, not encrypted storage or a general secret detector.

Reads are limited to 512 KiB plus one byte to detect overflow. Unknown/duplicate object fields, missing fields, malformed JSON, unsupported versions, and invalid request values are rejected with fixed messages that do not include file contents. Existing URL/body limits apply, with at most 100 headers and 32 KiB of header name/value bytes plus four framing bytes per field. GET requires empty plain text. Opening performs no network I/O; redirected output prints only the saved name and an instruction to open interactively.

Writing creates a sibling `<filename>.netscope-tmp` exclusively, writes all bytes, synchronizes that file, closes it, and renames it over the destination. On ordinary write/sync/rename failure the old file stays intact, and cleanup of this operation's temporary file is attempted. An already-existing temporary file is never overwritten or removed. A crash can leave that file behind; inspect it before manually removing it or choose another destination. Existing non-regular destinations, including symlinks, are refused. Unix temporary files are created with owner-only permissions (0600, subject to the process mask); replacement does not preserve the previous file's permissions. File operations are synchronous and intended for local filesystems. Directory synchronization and cross-platform power-loss durability are not claimed.

Tests cover deterministic serialization, Unicode/JSON body preservation, ordered duplicate headers, credential exclusion, invalid files and versions, bounded reads, injected partial-write failure, existing temporary-file protection, save confirmation/cancellation, reopened provenance and explicit Send, fixed screen buffers, and a local pseudo-terminal save/reopen flow. Only controlled local endpoints may be used during verification.
