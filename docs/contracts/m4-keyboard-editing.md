# Editing inside a field

This M4 slice extends the existing append-only editor. URL, body, header name/value, saved name, and saved path fields share cursor behaviour. Opening a field starts at its end. Left/Right move between extended Unicode grapheme boundaries; Home/End move to the beginning/end of the whole field, including a body containing newlines. Backspace removes the preceding grapheme and Delete removes the following one. Ordinary characters insert at the cursor. Ctrl+u clears the field. Ctrl+n and Tab insert a newline/tab only in a body. Enter saves and Esc discards the current edit. Validation failures keep editable text and put the cursor at its end.

A mutation may join neighbouring text into a new grapheme. After insertion/deletion, the cursor moves forward to the nearest valid boundary at or after its intended byte position. It never intentionally remains inside a grapheme. Movement uses the already locked unicode-segmentation implementation; rendering uses the existing unicode-width rules. These are text segmentation and terminal-width models, not a guarantee of identical glyph appearance in every terminal emulator.

The existing 16 KiB input limit counts UTF-8 bytes. Insertion that would exceed it changes neither the field nor the cursor. URL/body/header validation and all destination-reset, review-before-Send, save-preview, and credential-exclusion rules remain unchanged. No key used for cursor movement queues network or file work.

The terminal cursor marks the insertion point. Control characters remain escaped in the displayed field; those escapes are presentation, not replacements in the stored value. Cursor coordinates follow the escaped prefix and wrapped display width. Scrolling keeps the insertion point visible and resizing recomputes its screen position without changing the byte position. At an exactly full last row, a blank display row provides space for the end cursor. Small terminal handling and terminal restoration remain unchanged.

This slice does not add vertical cursor movement, selection, clipboard integration, bracketed paste handling, undo, or word-wise movement. Home/End are whole-field operations, not visual-line operations. Existing Ctrl+C, q-in-fields, and edit cancellation rules still apply.

Acceptance includes middle edits in every field type, multi-byte text, combining marks, joined emoji, deletion that joins graphemes, exact byte-limit rejection, start/end no-ops, control escaping, wrapping, resizing, edit cancellation, and Send/save gating. Fixed screens and the live local POST check verify the visible controls and actual bytes after a middle edit.
