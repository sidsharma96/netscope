# Replay transport decision

Selected October 10, 2026, before adding network dependencies: Hyper's HTTP/1 connection API, Tokio, and tokio-rustls with WebPKI roots. Hyper parses HTTP; Netscope does not implement a wire parser. One connection carries one GET. There is no connection pool, redirect follower, HTTP retry loop, proxy discovery, cookie store, content decompressor, or credential provider. Address resolution may produce several addresses to try before sending.

The connection parser accepts at most 100 response headers and 32 KiB including the status line; its read buffer is capped at 32 KiB. The same header-size limit applies to chunked trailers. Trailers are consumed but not retained. The application retains at most 2 MiB of body data; transport/TLS buffers are separate bounded overhead. A frame can contain excess bytes, but the application only checks whether one additional byte exists and never copies excess bytes into the result. Outgoing explicit headers are limited to 100 entries and 32 KiB including field separators, before sending. Host and Accept-Encoding: identity are added by the client; no other application headers are added.

Each operation uses a dedicated thread with a current-thread Tokio runtime. The terminal owns a cancellation sender and a one-result channel with capacity one. No progress-body queue exists. A single absolute deadline begins when Send is accepted. The worker owns partial response data outside the cancellable exchange future, so stopping the exchange preserves bytes already copied. The connection future is polled within that exchange and is dropped with it, closing the socket before a result is delivered. A completion already delivered wins over a later cancel; simultaneous readiness inside the worker prioritizes cancellation, then deadline, then exchange completion.

The OS resolver used by Tokio may continue a blocking lookup after cancellation. Runtime shutdown waits zero additional time for blocking resolver work. Such work cannot access the draft or produce a late UI result. It may outlive the worker thread until the OS lookup finishes. All socket and TLS work belongs to the cancellable exchange. This limitation does not imply remote rollback: a server may already have acted.

TLS verifies the certificate chain and destination hostname against bundled WebPKI roots. No user option bypasses verification. Test-only configuration can trust a generated local CA. HTTP/2 and HTTP/3 are not enabled; HTTPS advertises only HTTP/1.1.

References: [Hyper connection builder](https://docs.rs/hyper/1.12.0/hyper/client/conn/http1/struct.Builder.html), [Tokio runtime shutdown](https://docs.rs/tokio/latest/tokio/runtime/struct.Runtime.html#method.shutdown_timeout), and [rustls client configuration](https://docs.rs/rustls/latest/rustls/struct.ClientConfig.html). The milestone contract remains the acceptance checklist; this decision alone is not evidence of passing checks.
