# M8: directed TCP observations and plaintext framing/signaling

Implemented October 13, 2026. Follows M7's checked subset and keeps original packet evidence separate from derivation. Phase D proxy/CA work remains explicitly deferred by the roadmap.

## Sequence observations

Group supported TCP by directed source/destination IP+port in file order. SYN starts data at seq+1. A changed SYN, first SYN after an unanchored group, or SYN after FIN/RST starts a separate directed epoch. Repeated active SYN with the same anchor remains in that epoch. This conservative segmentation is not proof of globally unique connections; opposite directions are not paired. Without SYN, anchor at the first observed sequence and allow bounded earlier out-of-order bytes, while labelling connection start unknown. Sequence differences use signed modular distance within the bounded span; wrap-around is supported, half-space/unbounded histories are not.

Place retained payload by sequence, preserving declared-but-cut spans and holes between observations. ACK-only packets do not supply application bytes. FIN position marks a possible end (without inserting a data byte); inconsistent FIN positions or payload beyond FIN are noted. RST and skipped segments disqualify unambiguous observed end. Identical overlapping observations count repeats, which can be retransmission candidates or capture duplicates. Different observed bytes mark Conflict with no first/last-wins content policy. Missing/Conflict positions are not application zeros. Inspect only the longest uniquely observed prefix; never join across a gap/conflict.

Budgets: 128 directed epochs, 256 KiB per sequence span, 8 MiB sum of spans. Large sequence jumps/oversized segments are skipped and counted without allocating gaps. Epoch exhaustion counts unassigned TCP records and must not attach a newly refused epoch's data to an older one. Capture records and derived bytes remain bounded; no performance guarantee is asserted. Range display stops at 64 runs with notice, retaining underlying analysis.

## Plaintext HTTP/1.1 subset

Recognize GET/POST request starts and HTTP/1.1 response starts at the prefix origin. Headers/trailers: strict CRLF, ASCII token names, no folded/control-bearing values, at most 100 fields/32 KiB, each line <=4 KiB. At most eight sequential framing candidates. Support one decimal Content-Length, one Transfer-Encoding exactly chunked, header-only status boundaries, unframed requests with no body, and conditional close-delimited responses only when an unambiguous supported SYN-to-FIN span is observed. Repeated/comma lengths, other transfer codings and TE+CL stop with an explicit unsupported/ambiguous framing description. 101 stops HTTP continuation. Response request methods are not paired: display explicitly states framing is conditional, so HEAD/CONNECT semantics are not claimed. No general HTTP acceptance/parser conformance is claimed.

Chunk size is bounded hexadecimal (1..16 digits, size <= span limit); printable extension text is retained but its grammar/meaning is not validated. Record actual size-line/data offsets, require data CRLF, and require zero chunk plus completed valid trailer section. Missing delimiter, bad size, incomplete data/trailers and 1024-chunk limit remain distinct unresolved outcomes. Preserve prior complete chunks when later framing is unavailable. Show up to 64 chunks with display-limit notice. Removing chunk framing does not decompress content. Body preview <=4 KiB and header/trailer previews <=512 bytes are escaped; retained raw bytes remain separate.

## Available signaling

Recognize SDP-like complete uncompressed application/sdp text only when first line v=0 and o/s/t/m fields occur. ICE username and DTLS fingerprint markers strengthen a labelled rule, not a validated session, offer/answer role, peer identity, connectivity, WebRTC success or visible media. No SDP in compressed bodies, JSON envelopes or encrypted streams is invented.

For complete UDP on port 53, inspect ordinary DNS header/questions/answers with <=16 questions/32 answers, bounded labels/pointer traversal, backward pointers, and bounds on each field. Display IN A/AAAA answers; other answer RDATA stays described, authority/additional records not decoded. No DNSSEC, TCP DNS, resolver selection or load-balancing verdict. Recognize STUN candidates by top bits, magic cookie, exact aligned message length and <=64 bounded attribute frames; no attribute semantics, authentication or ICE success verdict. Invalid candidates have explicit explanations.
